# Aitho Design UI

[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)
[![npm](https://img.shields.io/npm/v/@aitho/ui.svg)](https://www.npmjs.com/package/@aitho/ui)
[![CI](https://github.com/AITHO/aitho-design-ui/actions/workflows/ci.yml/badge.svg)](https://github.com/AITHO/aitho-design-ui/actions/workflows/ci.yml)

A React component library built with TypeScript, [Radix UI](https://www.radix-ui.com/)
primitives and [Panda CSS](https://panda-css.com/). It ships form controls,
overlays, date pickers, tables, and navigation components, with light and dark
themes out of the box.

- **Documentation:** start with the [Theme Provider](docs/ThemeProvider.mdx) and
  [Toast Provider](docs/ToastProvider.mdx) guides. Run `npm run storybook` after
  installing the development dependencies to browse component examples and props.
- **License:** Apache-2.0. See [LICENSE](LICENSE) and [NOTICE](NOTICE).

## Requirements

- Node.js 22.x (for local development)
- React 18 or 19, and the matching `react-dom` (declared as peer dependencies)
- An ESM-compatible build tool that handles CSS imports
- Components can be rendered on the server: every module is marked
  `"use client"`, and `ThemeProvider` renders the light theme first and
  applies the theme saved in `localStorage` after mounting (see the
  [Theme Provider guide](docs/ThemeProvider.mdx) for the SSR caveats)

## Installation

```bash
npm install @aitho/ui
```

## Usage

Wrap your application in `ThemeProvider`, then import the components you need.
The styles are bundled with the components, so there is no CSS file to import.
Mount a single `ThemeProvider` at the application root. It applies the active
theme to the entire document; nested providers and independent brand scopes
on the same page are unsupported.

```tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { ThemeProvider } from "@aitho/ui";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <ThemeProvider>
      <App />
    </ThemeProvider>
  </React.StrictMode>,
);
```

```tsx
import { Button, Input, Label } from "@aitho/ui";

export function SignInForm() {
  return (
    <form>
      <Label htmlFor="email">Email</Label>
      <Input id="email" type="email" />
      <Button type="submit">Sign in</Button>
    </form>
  );
}
```

### Global styles

The bundled stylesheet is not limited to the components. It includes a CSS
reset (Panda CSS preflight) and sets the `font-family` of `<html>`, so it also
affects the rest of the page. The reset, base and component rules live in
cascade layers (`aitho-reset`, `aitho-base`, `aitho-tokens`, `aitho-recipes`,
`aitho-utilities`), so your own unlayered CSS always takes precedence; only the
theme custom properties and the `.shiki` code-block rule are unlayered. If your
application also uses cascade layers (for example Tailwind CSS v4), declare the
layer order explicitly to control which reset wins.

### Optional fonts

The library does not redistribute or automatically load Quatro, Space Mono or
any other external font. The CSS font stacks keep these names with a generic
fallback, so the components work when the fonts are not available.

If your project holds an Adobe Fonts license for Quatro, add your own Adobe
Fonts embed code to the application, for example in the `<head>` of
`index.html`, before the app loads:

```html
<link rel="stylesheet" href="https://use.typekit.net/your-project-id.css" />
```

Use the code generated by your own Adobe Fonts project: do not copy a project
ID from this library or from another application. Each consuming project is
responsible for its own license and Adobe Fonts configuration. If the font
does not load, Quatro and Space Mono fall back to their generic families.

`ToastProvider` and `useToast` are available for notifications, and `useTheme`
reads or switches the active theme. Every component is exported from the package
root; see the [public exports](lib/main.ts) for the full list and run Storybook
to browse examples.

Component types, including table and dialog types, are available from the package root:

```tsx
import type {
  DataItem,
  IColumn,
  TableSortDirection,
  DialogProps,
} from "@aitho/ui";
```

Import components and types only from `@aitho/ui`. Internal paths under `dist`
and `styled-system` are not public entry points. Applications updating from older
versions must replace deep imports with imports from the package root.

## Theming

Every component reads its colors from a set of CSS custom properties (`--color-primary`,
`--text-primary`, `--background-primary`, ...), each with a built-in light and dark
value. `useTheme()` switches between the two:

```tsx
import { useTheme } from "@aitho/ui";

function ThemeSwitch() {
  const { theme, toggleTheme } = useTheme();

  return <button onClick={toggleTheme}>Current theme: {theme}</button>;
}
```

To ship your own brand instead of the default palette, pass a `brand` prop to
`ThemeProvider`, a `light`/`dark` pair of token overrides. Anything you don't
override keeps the library's default value:

```tsx
import { Button, ThemeProvider, type BrandTokens } from "@aitho/ui";

const brand: BrandTokens = {
  light: {
    "color-primary": "#1a73e8",
    "color-primary-hover": "#1558b0",
    "text-on-primary": "#ffffff",
  },
  dark: {
    "color-primary": "#8ab4f8",
    "color-primary-hover": "#aecbfa",
    "text-on-primary": "#1a1a1a",
  },
};

export function BrandedApp() {
  return (
    <ThemeProvider brand={brand}>
      <Button>Continue</Button>
    </ThemeProvider>
  );
}
```

Overrides are independent: changing `color-primary` does not automatically
change its hover, active, disabled, opacity, or foreground tokens. Customize
the related tokens together and check the contrast of the resulting combinations.
See the [Theme Provider guide](docs/ThemeProvider.mdx) for the complete token
list, theme persistence, and provider limitations.

## Accessibility

The library uses Radix UI primitives where applicable. Accessibility also
depends on the labels, content, component configuration, and colors supplied
by the consuming application.

Storybook includes the axe accessibility panel for interactive checks on
component examples. There is no dedicated automated accessibility test suite
or accessibility check in CI. The current unit tests exercise component
behavior and do not constitute an accessibility audit. The project does not
claim WCAG conformance.

When integrating components or changing a palette, check keyboard navigation,
visible focus, accessible names, screen-reader announcements, and color contrast
in both themes. Test overlays for focus entry, Escape behavior, and focus
return when they close.

## Development

```bash
npm ci             # install dependencies
npm run storybook  # component workbench on http://localhost:6006
npm run typecheck  # panda codegen + TypeScript checks for app and build config
npm run build      # typecheck + vite build
npm run lint       # eslint
npm run format     # prettier --check
npm test           # unit tests
npm run test:coverage:ci
```

Open Storybook at `http://localhost:6006`. Coverage reports are generated in
`coverage/`; open `coverage/index.html` for the local report. The CI workflow
uploads coverage reports as an artifact. Its combined badge covers lint,
formatting, build, and unit tests. The CI badge becomes active after its workflow
runs on GitHub; local verification does not activate its URL. An accessibility
badge would require a dedicated test suite and is not currently provided.

New components are best scaffolded with the generator, which wires up the
recipe, the story and the test file for you:

```bash
npm run component:new
```
